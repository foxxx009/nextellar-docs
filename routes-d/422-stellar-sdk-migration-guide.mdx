# Stellar SDK Major Upgrades Migration Guide

Upgrading `@stellar/stellar-sdk` across major versions is critical for aligning with new Stellar protocol features, security fixes, and performance improvements. This guide provides an actionable roadmap for enumerating breaking changes, refactoring legacy SDK code with before-and-after examples, and executing a robust test plan.

---

## 1. Overview of Common Breaking Changes

Major SDK versions introduce structural refactors to accommodate Horizon RPC changes and Soroban smart contract primitives:

- **Namespace Reorganization**: Legacy top-level exports like `Server` or `SorobanRpc` are migrated to scoped namespaces (`Horizon.Server` and `rpc.Server`).
- **XDR Conversion Helpers**: Helper functions replaces manual `xdr.ScVal` constructors to enforce strict type checking.
- **Asynchronous Submission**: Transaction submissions shift from synchronous blocking responses to async submission + polling patterns.
- **Wallet Connection Interfaces**: Stellar wallet provider adapters updated to conform to standard event listeners.

## 2. Before & After Code Comparisons

### Horizon Server Instantiation

**Before (Legacy SDK):**
```typescript
import { Server } from '@stellar/stellar-sdk';

const server = new Server('https://horizon-testnet.stellar.org');
const account = await server.loadAccount('G...');
```

**After (Current SDK):**
```typescript
import { Horizon } from '@stellar/stellar-sdk';

const server = new Horizon.Server('https://horizon-testnet.stellar.org');
const account = await server.loadAccount('G...');
```

---

### Soroban RPC & Data Conversion

**Before (Legacy SDK):**
```typescript
import { SorobanRpc, xdr } from '@stellar/stellar-sdk';

const rpcServer = new SorobanRpc.Server('https://soroban-testnet.stellar.org');
const scVal = xdr.ScVal.scvI32(42);
```

**After (Current SDK):**
```typescript
import { rpc, nativeToScVal } from '@stellar/stellar-sdk';

const rpcServer = new rpc.Server('https://soroban-testnet.stellar.org');
const scVal = nativeToScVal(42, { type: 'i32' });
```

---

### Transaction Building & Submission

**Before (Legacy SDK):**
```typescript
const tx = new TransactionBuilder(sourceAccount, { fee: '100' })
  .addOperation(Operation.payment({ ... }))
  .build();

const result = await server.submitTransaction(tx);
```

**After (Current SDK):**
```typescript
const tx = new TransactionBuilder(sourceAccount, {
  fee: '100',
  networkPassphrase: Networks.TESTNET,
})
  .addOperation(Operation.payment({ ... }))
  .setTimeout(30)
  .build();

const sendResponse = await server.sendTransaction(tx);
// Async submission requires polling status
```

## 3. Recommended Migration Workflow

1. **Lock Current Dependencies**: Pin your current SDK version in `package.json` to prevent accidental intermediate updates during development.
2. **Audit SDK Usage**: Search the repository for deprecated SDK imports:
   ```bash
   grep -rn "from '@stellar/stellar-sdk'" src/
   ```
3. **Upgrade SDK Package**:
   ```bash
   npm install @stellar/stellar-sdk@latest --save-exact
   ```
4. **Fix Type Checking Errors**: Run the TypeScript compiler in no-emit mode to catch parameter type modifications:
   ```bash
   npx tsc --noEmit
   ```

---

## 4. Post-Upgrade Verification & Test Plan

To ensure no regression in transaction building, signing, or network calls:

1. **Unit Test Coverage**: Run test suite verifying `nativeToScVal` and `scValToNative` data conversions.
2. **Testnet Integration Sanity Check**:
   - Issue a test payment on Stellar Testnet.
   - Invoke a Soroban read-only contract method.
   - Verify error handling when network returns `tx_failed`.
3. **End-to-End Wallet Tests**: Verify Freight, Albedo, and WalletConnect signers properly handle envelopes produced by the updated SDK.
