# Stellar Node Operator Basics

Running a Stellar validator node lets you participate in consensus, serve Horizon data to your applications, and contribute to network decentralization. This guide covers the minimum viable setup, key monitoring signals, and how to safely upgrade.

---

## Node Types

| Type | Participates in consensus | Serves Horizon API | Resource need |
|------|--------------------------|-------------------|---------------|
| **Validator** | Yes (votes on ledger close) | Optional | High |
| **Full archival node** | No | Yes, full history | Very high (multi-TB) |
| **Watcher node** | No | Yes, recent history | Medium |

Most dApp operators run a watcher node for their own Horizon instance and optionally run a validator to strengthen the network.

## Installation

```bash
# Add the Stellar apt repository
curl -sSL https://apt.stellar.org/SDF.asc | sudo tee /etc/apt/trusted.gpg.d/stellar.asc
echo "deb https://apt.stellar.org focal stable" | sudo tee /etc/apt/sources.list.d/stellar.list
sudo apt-get update

# Install stellar-core and Horizon
sudo apt-get install -y stellar-core stellar-horizon

# Verify installation
stellar-core version
stellar-horizon version
```

## Reference stellar-core Config

Save as `/etc/stellar/stellar-core.cfg`:

```toml
# Network
NETWORK_PASSPHRASE="Public Global Stellar Network ; September 2015"
HTTP_PORT=11626
PUBLIC_HTTP_PORT=false

# Database (PostgreSQL)
DATABASE="postgresql://dbname=stellar user=stellar host=localhost"

# Peer discovery — use Stellar's seed nodes
KNOWN_PEERS=[
  "core-live-a.stellar.org:11625",
  "core-live-b.stellar.org:11625",
  "core-live-c.stellar.org:11625"
]
PREFERRED_PEERS_ONLY=false

# History archive (read existing history; write if you host your own)
[HISTORY.sdf]
get="curl -sf https://history.stellar.org/prd/core-live/core_live_001/{0} -o {1}"

# Your node's signing key (generate with: stellar-core gen-seed)
NODE_SEED="SXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX secret"
NODE_IS_VALIDATOR=true

# Quorum set — include SDF validators and well-known community validators
[QUORUM_SET]
THRESHOLD_PERCENT=66
VALIDATORS=[
  "$sdf_1", "$sdf_2", "$sdf_3",
  # Add additional trusted validators here
]

[VALIDATORS]
[VALIDATORS.sdf_1]
HOME_DOMAIN="stellar.org"
PUBLIC_KEY="GCKCDE6MVJXS4MJO4GEJVHGBJ5XNFKQRFADYUQHLXVFUQKRXMM3TZGM"
QUALITY="HIGH"

[VALIDATORS.sdf_2]
HOME_DOMAIN="stellar.org"
PUBLIC_KEY="GCB6BKFYV4HDOS4NWFKJRN2OAIGM6YMKUJQJVHWKNE5DCUV7JLXZZZK"
QUALITY="HIGH"

[VALIDATORS.sdf_3]
HOME_DOMAIN="stellar.org"
PUBLIC_KEY="GCBQ6JRBPF3SXQBQ6SO5MRBE7WVV4UCHYOSHKA4NQVUQXQSCILAKADSA"
QUALITY="HIGH"
```

Generate your node seed before first run:

```bash
stellar-core gen-seed
# Outputs: Secret seed: SXXX...
#          Public key:  GXXX...
```

Keep the secret seed offline and back it up securely.

## First Run and Catchup

```bash
# Initialize the database
stellar-core new-db --conf /etc/stellar/stellar-core.cfg

# Catch up to the current ledger (takes hours on first run)
stellar-core catchup current/1000 --conf /etc/stellar/stellar-core.cfg

# Start as a service
sudo systemctl enable stellar-core
sudo systemctl start stellar-core
```

## Monitoring

Key signals to watch:

| Signal | Where to find it | Healthy value |
|--------|-----------------|---------------|
| `state` | `GET http://localhost:11626/info` | `Synced!` |
| `ledger.age` | `/metrics` (Prometheus endpoint) | < 10 seconds |
| `peers.authenticated` | `/info` | ≥ 3 |
| `quorum.agree` | `/quorum` | matches your quorum set threshold |
| Disk usage | OS `df -h` | < 80 % |

Set up alerting on `state != Synced` and `ledger.age > 30s`.

```bash
# Quick health check
curl -s http://localhost:11626/info | python3 -m json.tool | grep '"state"'
```

## Upgrade Procedure

1. **Check the release notes** at [https://github.com/stellar/stellar-core/releases](https://github.com/stellar/stellar-core/releases) for breaking changes or required manual steps.
2. **Wait for a low-traffic period** (if possible) and notify your Horizon consumers.
3. Update the package:
   ```bash
   sudo apt-get update && sudo apt-get install stellar-core
   ```
4. Restart the service:
   ```bash
   sudo systemctl restart stellar-core
   ```
5. Verify the node re-syncs within ~2 minutes:
   ```bash
   watch -n 5 "curl -s http://localhost:11626/info | python3 -c \"import sys,json; d=json.load(sys.stdin); print(d['info']['state'])\""
   ```
6. If the node fails to sync, check `/var/log/stellar/stellar-core.log` and consult the release notes for migration steps.

## Accuracy Notes

- The `NODE_SEED` in the config is your **signing key** — treat it like a private key. Never commit it to version control.
- Quorum set misconfiguration can halt your node or cause it to vote on incorrect ledgers; use SDF's recommended quorum set as a starting point.
- History archives can be hosted on S3 or GCS; configure the `put` command in `[HISTORY]` if you want to publish your own archive.
- Testnet uses a different `NETWORK_PASSPHRASE`: `"Test SDF Network ; September 2015"`.
