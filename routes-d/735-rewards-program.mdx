# On-Chain Rewards Program Tutorial

This tutorial builds an on-chain rewards program where users earn points for actions and redeem them for token payouts. It covers point accrual, redemption, and mechanisms to prevent farming and double-claiming.

---

## Design Overview

| Component | Role |
|-----------|------|
| Rewards contract | Tracks points, controls accrual and redemption |
| Reward token | SAC or custom token paid out on redemption |
| Admin | Authorizes point grants; sets exchange rate |

---

## Data Model

```rust
#![no_std]
use soroban_sdk::{contract, contractimpl, contracttype, token, Address, Env, Symbol};

#[contracttype]
pub enum DataKey {
    Admin,
    Token,
    PointsPerToken, // how many points = 1 token unit
    Points(Address),
    LastAccrual(Address), // timestamp of last point grant
    AccrualCooldown,      // minimum seconds between accruals
}
```

## Initialization

```rust
#[contract]
pub struct Rewards;

#[contractimpl]
impl Rewards {
    pub fn initialize(
        env: Env,
        admin: Address,
        token: Address,
        points_per_token: i128,
        accrual_cooldown: u64,
    ) {
        assert!(!env.storage().instance().has(&DataKey::Admin), "already initialized");
        assert!(points_per_token > 0, "rate must be positive");

        env.storage().instance().set(&DataKey::Admin,          &admin);
        env.storage().instance().set(&DataKey::Token,          &token);
        env.storage().instance().set(&DataKey::PointsPerToken, &points_per_token);
        env.storage().instance().set(&DataKey::AccrualCooldown, &accrual_cooldown);
    }
```

## Accruing Points

Only the admin can grant points, preventing self-awarding.

```rust
    pub fn grant_points(env: Env, admin: Address, recipient: Address, points: i128) {
        admin.require_auth();
        let stored_admin: Address = env.storage().instance().get(&DataKey::Admin).unwrap();
        assert!(admin == stored_admin, "unauthorized");
        assert!(points > 0, "points must be positive");

        let cooldown: u64 = env.storage().instance().get(&DataKey::AccrualCooldown).unwrap();
        let last: u64     = env.storage().instance()
            .get(&DataKey::LastAccrual(recipient.clone()))
            .unwrap_or(0);

        assert!(
            env.ledger().timestamp() >= last + cooldown,
            "accrual cooldown active"
        );

        let prev: i128 = env.storage().instance()
            .get(&DataKey::Points(recipient.clone()))
            .unwrap_or(0);
        env.storage().instance().set(&DataKey::Points(recipient.clone()), &(prev + points));
        env.storage().instance().set(
            &DataKey::LastAccrual(recipient.clone()),
            &env.ledger().timestamp(),
        );

        env.events().publish((Symbol::new(&env, "grant"), recipient), points);
    }
```

## Redeeming Points

```rust
    pub fn redeem(env: Env, caller: Address, points: i128) {
        caller.require_auth();
        assert!(points > 0, "points must be positive");

        let balance: i128 = env.storage().instance()
            .get(&DataKey::Points(caller.clone()))
            .unwrap_or(0);
        assert!(balance >= points, "insufficient points");

        let rate: i128    = env.storage().instance().get(&DataKey::PointsPerToken).unwrap();
        let token_amount  = points / rate;
        assert!(token_amount > 0, "not enough points to redeem a full token");

        // Deduct the points that will be redeemed (floor division remainder stays)
        let points_used = token_amount * rate;
        env.storage().instance().set(
            &DataKey::Points(caller.clone()),
            &(balance - points_used),
        );

        let token: Address = env.storage().instance().get(&DataKey::Token).unwrap();
        token::Client::new(&env, &token).transfer(
            &env.current_contract_address(),
            &caller,
            &token_amount,
        );

        env.events().publish((Symbol::new(&env, "redeem"), caller), (points_used, token_amount));
    }
}
```

## A Small Off-Chain Integration

```ts
import { Contract, SorobanRpc, TransactionBuilder, Networks, BASE_FEE } from "@stellar/stellar-sdk";

const server    = new SorobanRpc.Server("https://soroban-testnet.stellar.org");
const CONTRACT  = "C...";

// Called by your backend after a user completes a qualifying action
async function grantPoints(adminKeypair: Keypair, userAddress: string, points: number) {
  const account  = await server.getAccount(adminKeypair.publicKey());
  const contract = new Contract(CONTRACT);

  const tx = new TransactionBuilder(account, { fee: BASE_FEE, networkPassphrase: Networks.TESTNET })
    .addOperation(contract.call("grant_points", /* admin, recipient, points as xdr */))
    .setTimeout(30)
    .build();

  const prepared = await server.prepareTransaction(tx);
  prepared.sign(adminKeypair);
  return server.sendTransaction(prepared);
}
```

## Abuse Prevention

| Attack | Defense |
|--------|---------|
| Self-granting points | `grant_points` requires admin auth |
| Rapid point farming | `AccrualCooldown` enforces minimum interval between grants per address |
| Redeeming fractional points | Floor division — remainder stays in balance |
| Draining reward pool | Admin controls fund deposits; monitor contract token balance |
| Sybil accounts | Off-chain identity check (e.g. KYC or attestation) before granting points |

---

## Accuracy Notes

- The reward token must be pre-deposited into the contract address before any redemption can succeed.
- `PointsPerToken` uses integer division; set the rate and point values in the same unit scale (e.g. 100 points = 1 token in stroops).
- Use `env.storage().persistent()` for user point balances if users may go inactive for extended periods.
- Emit events for every grant and redemption so an indexer can build a leaderboard without scanning all contract storage.
