# AMM Implementation Guide on Soroban

An automated market maker (AMM) replaces the traditional order book with a deterministic pricing formula. Liquidity providers deposit token pairs into a pool; traders swap against the pool at a price set by the formula. This guide walks through the key design decisions and a reference Soroban implementation.

---

## Pricing Formula Comparison

| Formula | Equation | Behaviour | Best for |
|---|---|---|---|
| **Constant product** | `x · y = k` | Price moves along a hyperbola | General-purpose token pairs |
| **Constant sum** | `x + y = k` | Fixed 1:1 price until pool drains | Stablecoins (fragile in practice) |
| **Stableswap (hybrid)** | `A·n^n·Σx + D = A·D·n^n + D^(n+1)/(n^n·Πx)` | Flat near peg, curved at extremes | Pegged assets (USDC/USDC) |
| **Weighted** | `x^w1 · y^w2 = k` | Asymmetric weights shift equilibrium price | Index pools, treasury diversification |

Constant product (`x · y = k`) is the right starting point for most Soroban AMMs. Its single invariant is cheap to verify on-chain, and the math is well-understood.

---

## Fee and Slippage Handling

### Trading Fee

Every swap takes a percentage fee from the input amount before applying the pricing formula. The fee stays in the pool, accruing to liquidity providers proportionally.

With a 0.3 % fee and input amount `Δx`:

```
effective_input = Δx × (1 - fee)   // e.g. 0.997 × Δx
Δy = y × effective_input / (x + effective_input)
```

### Price Impact (Slippage)

Slippage is the difference between the quoted price and the execution price caused by the trade's own size shifting the pool ratio. It grows with trade size relative to pool depth.

```
spot_price_before  = y / x
spot_price_after   = (y - Δy) / (x + Δx)
price_impact       = (spot_price_after - spot_price_before) / spot_price_before
```

### Minimum Output Guard

Every swap function should accept a `min_out` parameter. Revert if the output would fall below it — this protects users from sandwich attacks and unexpected price movement.

## Reference Design

### Pool Invariant

Store two token balances and a `k` value. After every swap or liquidity change, recompute and persist `k = reserve_a * reserve_b`.

### Liquidity Token

Mint LP tokens representing proportional pool ownership. The share minted on deposit is:

```
shares = total_shares × min(Δa / reserve_a, Δb / reserve_b)
```

On the very first deposit, set `shares = sqrt(Δa × Δb)` (geometric mean) to anchor the initial price.

## Soroban Contract

```rust
// contracts/amm/src/lib.rs
#![no_std]
use soroban_sdk::{
    contract, contractimpl, contracttype, token, Address, Env, IntoVal,
};

#[contracttype]
pub struct Pool {
    pub reserve_a: i128,
    pub reserve_b: i128,
    pub total_shares: i128,
    pub fee_bps: i128, // e.g. 30 = 0.30%
}

const POOL_KEY: &str = "pool";
const BPS: i128 = 10_000;

#[contract]
pub struct AmmContract;

#[contractimpl]
impl AmmContract {
    /// Initialize the pool. Call once after deployment.
    pub fn initialize(env: Env, fee_bps: i128) {
        assert!(fee_bps < BPS, "fee must be < 100%");
        env.storage().instance().set(
            &POOL_KEY,
            &Pool {
                reserve_a: 0,
                reserve_b: 0,
                total_shares: 0,
                fee_bps,
            },
        );
    }

    /// Deposit token_a and token_b; receive LP shares in return.
    pub fn add_liquidity(
        env: Env,
        caller: Address,
        token_a: Address,
        token_b: Address,
        amount_a: i128,
        amount_b: i128,
        min_shares: i128,
    ) -> i128 {
        caller.require_auth();
        let mut pool: Pool = env.storage().instance().get(&POOL_KEY).unwrap();

        let shares = if pool.total_shares == 0 {
            // First deposit: geometric mean
            isqrt(amount_a * amount_b)
        } else {
            let from_a = pool.total_shares * amount_a / pool.reserve_a;
            let from_b = pool.total_shares * amount_b / pool.reserve_b;
            from_a.min(from_b)
        };

        assert!(shares >= min_shares, "insufficient shares minted");

        // Transfer tokens from caller to contract
        let client_a = token::Client::new(&env, &token_a);
        let client_b = token::Client::new(&env, &token_b);
        client_a.transfer(&caller, &env.current_contract_address(), &amount_a);
        client_b.transfer(&caller, &env.current_contract_address(), &amount_b);

        pool.reserve_a += amount_a;
        pool.reserve_b += amount_b;
        pool.total_shares += shares;
        env.storage().instance().set(&POOL_KEY, &pool);

        shares
    }

    /// Swap exact `amount_in` of token_a for token_b.
    pub fn swap_a_for_b(
        env: Env,
        caller: Address,
        token_a: Address,
        token_b: Address,
        amount_in: i128,
        min_out: i128,
    ) -> i128 {
        caller.require_auth();
        let mut pool: Pool = env.storage().instance().get(&POOL_KEY).unwrap();

        let effective = amount_in * (BPS - pool.fee_bps) / BPS;
        let amount_out = pool.reserve_b * effective / (pool.reserve_a + effective);

        assert!(amount_out >= min_out, "slippage exceeded");

        let client_a = token::Client::new(&env, &token_a);
        let client_b = token::Client::new(&env, &token_b);
        client_a.transfer(&caller, &env.current_contract_address(), &amount_in);
        client_b.transfer(&env.current_contract_address(), &caller, &amount_out);

        pool.reserve_a += amount_in;
        pool.reserve_b -= amount_out;
        // Fee stays in pool — k grows slightly, benefiting LPs
        env.storage().instance().set(&POOL_KEY, &pool);

        amount_out
    }

    /// Burn LP shares; withdraw proportional reserves.
    pub fn remove_liquidity(
        env: Env,
        caller: Address,
        token_a: Address,
        token_b: Address,
        shares: i128,
    ) -> (i128, i128) {
        caller.require_auth();
        let mut pool: Pool = env.storage().instance().get(&POOL_KEY).unwrap();

        let amount_a = shares * pool.reserve_a / pool.total_shares;
        let amount_b = shares * pool.reserve_b / pool.total_shares;

        pool.reserve_a -= amount_a;
        pool.reserve_b -= amount_b;
        pool.total_shares -= shares;
        env.storage().instance().set(&POOL_KEY, &pool);

        let client_a = token::Client::new(&env, &token_a);
        let client_b = token::Client::new(&env, &token_b);
        client_a.transfer(&env.current_contract_address(), &caller, &amount_a);
        client_b.transfer(&env.current_contract_address(), &caller, &amount_b);

        (amount_a, amount_b)
    }

    pub fn get_pool(env: Env) -> Pool {
        env.storage().instance().get(&POOL_KEY).unwrap()
    }
}

fn isqrt(n: i128) -> i128 {
    if n == 0 { return 0; }
    let mut x = n;
    let mut y = (x + 1) / 2;
    while y < x {
        x = y;
        y = (x + n / x) / 2;
    }
    x
}
```

## Client Integration

```ts
// lib/amm.ts
import {
  Contract,
  Networks,
  TransactionBuilder,
  BASE_FEE,
  rpc,
  nativeToScVal,
  Address,
} from '@stellar/stellar-sdk';

const RPC_URL = process.env.NEXT_PUBLIC_RPC_URL!;
const AMM_CONTRACT = process.env.NEXT_PUBLIC_AMM_CONTRACT!;

export async function swapAForB(
  callerKeypair: { publicKey(): string; sign(tx: any): void },
  tokenA: string,
  tokenB: string,
  amountIn: bigint,
  minOut: bigint,
): Promise<bigint> {
  const server = new rpc.Server(RPC_URL);
  const account = await server.getAccount(callerKeypair.publicKey());

  const contract = new Contract(AMM_CONTRACT);
  const tx = new TransactionBuilder(account, {
    fee: BASE_FEE,
    networkPassphrase: Networks.TESTNET,
  })
    .addOperation(
      contract.call(
        'swap_a_for_b',
        new Address(callerKeypair.publicKey()).toScVal(),
        new Address(tokenA).toScVal(),
        new Address(tokenB).toScVal(),
        nativeToScVal(amountIn, { type: 'i128' }),
        nativeToScVal(minOut, { type: 'i128' }),
      ),
    )
    .setTimeout(30)
    .build();

  const prepared = await server.prepareTransaction(tx);
  callerKeypair.sign(prepared);
  const result = await server.sendTransaction(prepared);
  // Parse result.returnValue from i128 ScVal
  return BigInt(result.returnValue?.value()?.toString() ?? '0');
}
```

## Key Design Decisions

### Fee Stays in Reserves

The fee is not separately tracked — it increases `reserve_a` without a corresponding decrease in `reserve_b`, so `k` grows after every trade. LPs collect fees by holding a share of a pool whose `k` strictly increases.

### No Oracle Dependency

The constant-product price is entirely determined by pool balances. No external oracle is needed, which reduces attack surface. For protocols that need a reliable price signal, see the TWAP guide (issue #734) which shows how to read a time-weighted average from a pool's historical balance snapshots.

### Integer Arithmetic

All amounts are `i128` (Soroban's largest integer type). Prices are computed as ratios to avoid floating-point precision issues. The `isqrt` helper uses Newton's method and is safe for values up to `i128::MAX`.
