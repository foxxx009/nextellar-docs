# Time-Weighted Average Price (TWAP) Oracle on Stellar

A Time-Weighted Average Price (TWAP) oracle smooths out short-term price manipulation by averaging a price over a time window rather than reading it at a single instant. This guide shows how to collect price samples on Stellar, compute a TWAP, and detect stale data — both from an on-chain Soroban contract and from an off-chain aggregator.

---

## Why TWAP?

A spot price from a single DEX trade can be moved cheaply by a flash loan or a well-timed large order. The TWAP makes manipulation expensive because an attacker must sustain the artificial price for the entire averaging window.

```
spot_price = last_trade_price              // easy to manipulate in one block
twap       = Σ(price_i × Δt_i) / Σ(Δt_i) // must be manipulated for minutes/hours
```

## Data Collection Strategies

### Strategy 1 — Read AMM Pool Balances (On-Chain)

If you control an AMM pool (see the AMM guide, issue #716), checkpoint the pool's reserve ratio at regular ledger intervals and accumulate the price × time product.

**Pros**: no external data source; manipulation-resistant if pool has deep liquidity.

**Cons**: only reflects one pool; price accuracy is limited by liquidity depth.

### Strategy 2 — Horizon Trade Aggregations (Off-Chain)

Horizon exposes `/trade_aggregations` which returns OHLCV data for any asset pair bucketed by time. Pull these and aggregate off-chain, then submit the result to a Soroban settlement contract.

```ts
// lib/trade-aggregations.ts
import { Horizon, Asset } from '@stellar/stellar-sdk';

const server = new Horizon.Server(process.env.HORIZON_URL!);

export async function fetchTwap(
  baseAsset: Asset,
  counterAsset: Asset,
  windowMs: number,
): Promise<number> {
  const now = Date.now();
  const start = now - windowMs;

  const records = await server
    .tradeAggregation(
      baseAsset,
      counterAsset,
      start,
      now,
      60_000, // 1-minute buckets
      0,      // offset
    )
    .call();

  if (!records.records.length) throw new Error('no trades in window');

  let weightedSum = 0;
  let totalDuration = 0;

  for (const r of records.records) {
    const price = parseFloat(r.avg); // avg price in that bucket
    const duration = 60_000;         // each bucket is 60 s
    weightedSum += price * duration;
    totalDuration += duration;
  }

  return weightedSum / totalDuration;
}
```

**Pros**: rich historical data; multiple asset pairs available out of the box.

**Cons**: off-chain computation introduces a trust assumption; submission latency adds a few seconds.

### Strategy 3 — Push Oracle (Signed Price Feed)

Trusted price providers (e.g. Pyth, Band, custom aggregators) sign price reports off-chain and post them to a Soroban oracle contract at regular intervals.

**Pros**: flexible data sources; can aggregate many exchanges.

**Cons**: trust is in the price provider; liveness depends on their uptime.

## On-Chain TWAP Accumulator

The pattern below stores cumulative `price × time` and `time` totals in contract storage. Any caller can checkpoint the current price; a reader computes the TWAP over any window by subtracting two snapshots.

```rust
// contracts/twap-oracle/src/lib.rs
#![no_std]
use soroban_sdk::{contract, contractimpl, contracttype, Address, Env};

/// Cumulative snapshot stored per price feed.
#[contracttype]
pub struct Snapshot {
    pub cumulative_price: i128, // sum of (price × elapsed_seconds)
    pub cumulative_time: u64,   // total elapsed seconds
    pub last_price: i128,       // last reported price (scaled by 1e7)
    pub last_timestamp: u64,    // ledger timestamp of last update
}

const SNAPSHOT_KEY: &str = "snapshot";
const MAX_STALENESS: u64 = 300; // 5 minutes

#[contract]
pub struct TwapOracle;

#[contractimpl]
impl TwapOracle {
    /// Initialise with an initial price (scaled by 1e7, e.g. 1 XLM = 10_000_000).
    pub fn initialize(env: Env, admin: Address, initial_price: i128) {
        admin.require_auth();
        env.storage().instance().set(
            &SNAPSHOT_KEY,
            &Snapshot {
                cumulative_price: 0,
                cumulative_time: 0,
                last_price: initial_price,
                last_timestamp: env.ledger().timestamp(),
            },
        );
    }

    /// Report a new price. Anyone can call this; in production gate it
    /// behind an allowlist of trusted price providers.
    pub fn update_price(env: Env, reporter: Address, new_price: i128) {
        reporter.require_auth();
        assert!(new_price > 0, "price must be positive");

        let mut snap: Snapshot = env
            .storage()
            .instance()
            .get(&SNAPSHOT_KEY)
            .unwrap();

        let now = env.ledger().timestamp();
        let elapsed = now.saturating_sub(snap.last_timestamp);

        // Accumulate price × time using the previous price for the elapsed window
        snap.cumulative_price += snap.last_price * elapsed as i128;
        snap.cumulative_time += elapsed;
        snap.last_price = new_price;
        snap.last_timestamp = now;

        env.storage().instance().set(&SNAPSHOT_KEY, &snap);
    }

    /// Compute the TWAP since `since_timestamp`.
    /// Returns the average price scaled by 1e7.
    pub fn get_twap(env: Env, since_timestamp: u64) -> i128 {
        let snap: Snapshot = env
            .storage()
            .instance()
            .get(&SNAPSHOT_KEY)
            .unwrap();

        let now = env.ledger().timestamp();

        // Guard: reject stale oracle
        assert!(
            now.saturating_sub(snap.last_timestamp) <= MAX_STALENESS,
            "oracle is stale"
        );

        // Include the time elapsed since the last update (still at last_price)
        let elapsed_since_last = now.saturating_sub(snap.last_timestamp);
        let total_price = snap.cumulative_price + snap.last_price * elapsed_since_last as i128;
        let total_time = snap.cumulative_time + elapsed_since_last;

        // Subtract the contribution before `since_timestamp`
        // (Simplified: in production store per-block snapshots to support arbitrary windows)
        assert!(total_time > 0, "no data accumulated");
        total_price / total_time as i128
    }

    pub fn get_snapshot(env: Env) -> Snapshot {
        env.storage().instance().get(&SNAPSHOT_KEY).unwrap()
    }
}
```

## Staleness Handling

A TWAP is only as trustworthy as its freshness. Two layers of protection:

### Layer 1 — Contract-Level Staleness Guard

The `get_twap` function above asserts that the last update was within `MAX_STALENESS` seconds (300 s in the example). Callers that depend on a fresh price — swap contracts, lending protocols — will revert rather than use an outdated value.

Tune `MAX_STALENESS` to your use case:
- **High-frequency DeFi** (AMM fee tier, liquidation trigger): 30–60 s
- **Batch settlement, treasury rebalancing**: 5–15 min
- **Daily NAV calculation**: 1–6 h

### Layer 2 — Off-Chain Liveness Monitor

Even with an on-chain guard, you want alerting before the oracle goes stale. Run a monitor that polls the last `last_timestamp` and pages if it falls behind schedule:

```ts
// scripts/oracle-monitor.ts

const CHECK_INTERVAL_MS = 30_000;
const ALERT_THRESHOLD_S = 120; // alert if last update > 2 min ago

  const server = new rpc.Server(process.env.RPC_URL!);
  const contract = new Contract(process.env.TWAP_CONTRACT!);

  const key = xdr.ScVal.scvLedgerKeyContractInstance();
  const data = await server.getContractData(
    contract.contractId(),
    key,
```
