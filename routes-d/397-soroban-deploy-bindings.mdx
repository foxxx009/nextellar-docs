# Soroban Contract Deploy & Bindings

This guide covers deploying a Soroban smart contract to Stellar and generating TypeScript bindings for type-safe frontend integration. You'll learn how to install the WASM binary, deploy it to Testnet, generate a typed SDK client, and wire it into a Nextellar app.

---

## Prerequisites

- Rust with `wasm32-unknown-unknown` target installed
- Stellar CLI installed (`stellar`)
- A funded Testnet identity (see [Contracts Quick Start](/docs/getting-started/contracts-quick-start) for setup)

Run `npx nextellar doctor` to verify your environment:

```bash
npx nextellar doctor
```

---

## Deploy Steps

### 1. Build the Contract

From your project root, build the contract to WASM:

```bash
npm run contracts:build
```

This produces a `.wasm` binary at `contracts/target/wasm32-unknown-unknown/release/<contract_name>.wasm`.

### 2. Optimize the Binary

Reduce the WASM file size before deployment:

```bash
stellar contract optimize \
  --wasm contracts/target/wasm32-unknown-unknown/release/hello_world.wasm \
  --out contracts/target/wasm32-unknown-unknown/release/hello_world.optimized.wasm
```

Optimization strips debug symbols and applies size reductions. For a minimal contract this typically reduces the binary from ~200 KB to ~30 KB.

### 3. Create a Funded Testnet Identity

If you haven't already:

```bash
stellar keys generate alice --network testnet --fund
```

This generates a keypair, stores it locally as `alice`, and funds it with test XLM via Friendbot.

### 4. Deploy to Testnet

```bash
stellar contract deploy \
  --wasm contracts/target/wasm32-unknown-unknown/release/hello_world.optimized.wasm \
  --source alice \
  --network testnet
```

On success, the CLI prints a contract address starting with `C`. Copy it — you'll need it for bindings and frontend configuration.

### 5. Store the Contract ID

Add the deployed contract ID to your environment:

```bash
# .env.local
NEXT_PUBLIC_HELLO_WORLD_CONTRACT_ID=<paste your contract ID>
```

## Bindings Generation

TypeScript bindings generate a typed SDK client from the contract's WASM binary. This gives you compile-time type checking, autocompletion, and documented function signatures.

### 1. Generate the Bindings

```bash
stellar contract bindings typescript \
  --wasm contracts/target/wasm32-unknown-unknown/release/hello_world.wasm \
  --out-dir src/contracts/hello_world
```

This creates a directory at `src/contracts/hello_world/` containing:

```
src/contracts/hello_world/
├── index.ts          # Re-exports the client
└── hello_world.ts    # Generated typed client
```

### 2. Import the Generated Client

Use the generated client in your React components:

```tsx
import { HelloContractClient } from '@/contracts/hello_world';
```

### 3. Use with useSorobanContract

The generated client defines function names and argument types. Pass these to the `useSorobanContract` hook:

```tsx
'use client';

import { useState } from 'react';
import { useSorobanContract } from '@/hooks/useSorobanContract';

export default function HelloContractDemo() {
  const { callFunction, loading, error } = useSorobanContract({
    contractId: process.env.NEXT_PUBLIC_HELLO_WORLD_CONTRACT_ID!,
  });

  const [greeting, setGreeting] = useState('');

  const handleInvoke = async () => {
    const result = (await callFunction('hello', [
      { value: 'friend', type: 'symbol' },
    ])) as string[];
    setGreeting(result.join(' '));
  };

  return (
    <div>
      <button onClick={handleInvoke} disabled={loading}>
        {loading ? 'Calling...' : 'Say Hello'}
      </button>
      {greeting && <p>{greeting}</p>}
      {error && <p>Error: {error.message}</p>}
    </div>
  );
}
```

## Complete Example

Here's a full workflow from a fresh contract to a working frontend invocation:

### Contract (`contracts/hello_world/src/lib.rs`)

```rust
#![no_std]
use soroban_sdk::{contract, contractimpl, symbol_short, vec, Env, Symbol, Vec};

#[contract]
pub struct HelloContract;

#[contractimpl]
impl HelloContract {
    pub fn hello(env: Env, to: Symbol) -> Vec<Symbol> {
        vec![&env, symbol_short!("Hello"), to]
    }
}
```

### Build, Deploy, Generate

```bash
# Build
npm run contracts:build

# Optimize
stellar contract optimize \
  --wasm contracts/target/wasm32-unknown-unknown/release/hello_world.wasm \
  --out contracts/target/wasm32-unknown-unknown/release/hello_world.optimized.wasm

# Deploy
CONTRACT_ID=$(stellar contract deploy \
  --wasm contracts/target/wasm32-unknown-unknown/release/hello_world.optimized.wasm \
  --source alice \
  --network testnet)

# Generate bindings
stellar contract bindings typescript \
  --wasm contracts/target/wasm32-unknown-unknown/release/hello_world.wasm \
  --out-dir src/contracts/hello_world

# Set contract ID in environment
echo "NEXT_PUBLIC_HELLO_WORLD_CONTRACT_ID=$CONTRACT_ID" >> .env.local
```

### Frontend Page (`src/app/hello-contract/page.tsx`)

```tsx
'use client';

import { useState } from 'react';
import { useSorobanContract } from '@/hooks/useSorobanContract';

export default function HelloContractPage() {
  const { callFunction, loading, error } = useSorobanContract({
    contractId: process.env.NEXT_PUBLIC_HELLO_WORLD_CONTRACT_ID!,
  });

  const [result, setResult] = useState('');

  const invoke = async () => {
    const response = (await callFunction('hello', [
      { value: 'world', type: 'symbol' },
    ])) as string[];
    setResult(response.join(' '));
  };

  return (
    <main>
      <h1>Soroban Hello World</h1>
      <button onClick={invoke} disabled={loading}>
        {loading ? 'Calling...' : 'Invoke Contract'}
      </button>
      {result && <p>Result: {result}</p>}
      {error && <p>Error: {error.message}</p>}
    </main>
  );
}
```

Visit `/hello-contract` and click the button — you should see `Hello world`.

## Troubleshooting

### `stellar: command not found`

Install the Stellar CLI, then re-run `npx nextellar doctor` to confirm it's on your `PATH`.

### Bindings generation fails with missing WASM

Ensure the contract is built before generating bindings. The `--wasm` path must point to a compiled binary, not the Rust source.

### Frontend shows placeholder contract ID

`NEXT_PUBLIC_*` variables are inlined at build time. Confirm `.env.local` has the correct value and restart `npm run dev`.

### Deploy fails with insufficient funds

Generate a fresh funded identity:

```bash
stellar keys generate alice --network testnet --fund
```
