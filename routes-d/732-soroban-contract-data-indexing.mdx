# Soroban Contract Data Indexing

Soroban contract state lives inside the Stellar ledger and is not directly queryable like a relational database. Indexing bridges that gap: you capture contract events or storage snapshots and store them in a queryable backend so your dApp can answer questions like "show me all open orders" without iterating ledger state at query time.

---

## Approaches Compared

| Approach | How it works | Query latency | Operational cost | Best for |
|----------|-------------|--------------|-----------------|---------|
| **Soroban RPC `getContractData`** | Fetch specific storage keys on demand | Real-time | None | Reading a single known key |
| **Horizon event stream** | Stream `ContractEvents` from Horizon SSE endpoint | ~5 s lag | None | Small event volume, no history needed |
| **Custom indexer (Node.js / Python)** | Poll `getLedgers` or `getEvents`, write to Postgres/Redis | ~5–30 s lag | Self-hosted DB | Medium projects, full control |
| **Mercury / SubQuery / StellarX indexers** | Hosted services that index all Soroban events | Near real-time | Managed pricing | Production apps needing rich queries |

---

## Storage Strategies

Soroban has three storage tiers — pick the right one for indexed data:

| Storage tier | TTL behavior | Use for |
|-------------|-------------|---------|
| `instance` | Tied to contract instance; expires together | Config, admin key |
| `persistent` | Independent TTL; survives contract expiry | Order books, balances, user records |
| `temporary` | Short TTL, cheapest | Nonces, rate-limit counters |

Emit a contract event for every state mutation. Indexers consume events and reconstruct current state without needing direct storage access.

## Emitting Indexable Events

```rust
use soroban_sdk::{Env, Symbol, Address};

fn emit_transfer(env: &Env, from: &Address, to: &Address, amount: i128) {
    env.events().publish(
        (Symbol::new(env, "transfer"), from.clone(), to.clone()),
        amount,
    );
}
```

Events are part of the transaction metadata and are returned by `getTransaction` and the Soroban RPC `getEvents` endpoint.

## Custom Indexer: Small Implementation

A Node.js indexer that tails Soroban events and writes them to Postgres:

```ts
import { SorobanRpc } from "@stellar/stellar-sdk";
import { Pool } from "pg";

const server = new SorobanRpc.Server("https://soroban-testnet.stellar.org");
const db     = new Pool({ connectionString: process.env.DATABASE_URL });
const CONTRACT_ID = "C...";

async function runIndexer() {
  // Load the last indexed ledger from the DB
  const { rows } = await db.query("SELECT last_ledger FROM indexer_state WHERE id = 1");
  let cursor      = rows[0]?.last_ledger ?? "0000000000000000";

  while (true) {
    const response = await server.getEvents({
      startLedger: parseInt(cursor, 16) + 1,
      filters: [{ type: "contract", contractIds: [CONTRACT_ID] }],
      limit: 100,
    });

    for (const event of response.events) {
      await db.query(
        "INSERT INTO events (ledger, tx_hash, topic, value) VALUES ($1,$2,$3,$4) ON CONFLICT DO NOTHING",
        [event.ledger, event.txHash, JSON.stringify(event.topic), JSON.stringify(event.value)]
      );
    }

    if (response.events.length > 0) {
      const last = response.events[response.events.length - 1];
      cursor     = last.ledger.toString(16).padStart(16, "0");
      await db.query(
        "INSERT INTO indexer_state (id, last_ledger) VALUES (1,$1) ON CONFLICT (id) DO UPDATE SET last_ledger=$1",
        [cursor]
      );
    }

    await new Promise((r) => setTimeout(r, 5_000)); // poll every ~1 ledger close
  }
}

runIndexer().catch(console.error);
```

## Querying the Index

Once events are in Postgres, standard SQL works:

```sql
-- All transfer events for a given address
SELECT ledger, tx_hash, value
FROM events
WHERE topic::jsonb @> '["transfer"]'
  AND topic::jsonb @> '[{"address": "GRECIPIENT..."}]'
ORDER BY ledger DESC
LIMIT 50;
```

Expose this via a REST endpoint in your dApp backend.

## Using a Hosted Indexer (Mercury)

[Mercury](https://mercurydata.app) is a hosted Soroban indexer. Register your contract and query via GraphQL:

```graphql
query RecentTransfers {
  contractEvents(
    contractId: "C..."
    topic0: "transfer"
    limit: 20
  ) {
    ledger
    txHash
    value
  }
}
```

No infrastructure to manage; trade-off is dependency on a third-party service.

---

## Schema Design Tips

- Store raw event topic and value as JSONB so you can re-process without re-indexing.
- Add a `ledger` index and a `contract_id` index for fast filtered queries.
- Use `ON CONFLICT DO NOTHING` on insert so a crashed indexer can safely replay from the last checkpoint without duplicates.
- Store the last successfully indexed ledger atomically with the event batch in a single transaction.

---

## Accuracy Notes

- `getEvents` on the Soroban RPC returns at most the last 17,280 ledgers (~24 hours); bootstrap historical data from an archive node or a hosted indexer that pre-indexes from genesis.
- Event topic fields are XDR-encoded; decode with `xdr.ScVal.fromXDR(topic, "base64")` before storing or comparing.
- `getContractData` for direct storage reads requires knowing the exact `ScVal` key; use it for point lookups, not scans.
