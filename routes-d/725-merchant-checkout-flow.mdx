# Merchant Checkout Flow Tutorial

This tutorial walks through a full merchant checkout on Stellar: the merchant generates a payment request, the buyer's wallet sends the transaction, and the merchant backend verifies settlement before releasing the order.

---

## Flow Overview

```
Buyer (wallet)          Merchant Backend         Stellar Network
     |                        |                        |
     |← payment details ──── |                        |
     |                        |                        |
     |─── send tx ──────────────────────────────────→ |
     |                        |                        |
     |                        |← stream events ─────── |
     |                        |  (payment received)    |
     |                        |                        |
     |←── order confirmed ─── |                        |
```

---

## Step 1 — Generate a Payment Request

The merchant creates a unique memo and expected amount for each order. The memo ties the payment to the order in the merchant's database.

```ts
import crypto from "crypto";

interface OrderRequest {
  orderId:     string;
  amount:      string;
  assetCode:   string;
  assetIssuer: string | null;
  destination: string;
  memo:        string;
}

function createPaymentRequest(orderId: string, amount: string): OrderRequest {
  const memo = crypto.createHash("sha256").update(orderId).digest("hex").slice(0, 28);
  return {
    orderId,
    amount,
    assetCode:   "XLM",
    assetIssuer: null,
    destination: process.env.MERCHANT_PUBLIC_KEY!,
    memo,
  };
}
```

The memo is a deterministic hash of the order ID, so the backend can look up which order a payment corresponds to without storing a separate mapping table.

## Step 2 — Present the Payment URI to the Buyer

Stellar SEP-0007 defines a URI scheme that compatible wallets can open directly:

```ts
function buildStellarUri(req: OrderRequest): string {
  const params = new URLSearchParams({
    destination: req.destination,
    amount:      req.amount,
    asset_code:  req.assetCode,
    memo:        req.memo,
    memo_type:   "MEMO_TEXT",
    msg:         `Payment for order ${req.orderId}`,
  });
  return `web+stellar:pay?${params.toString()}`;
}
```

Show the URI as a QR code or a deep-link button in the checkout UI.

## Step 3 — Verify Settlement on the Merchant Backend

Stream Horizon for incoming payments to the merchant account. Match by memo and amount.

```ts
import Horizon from "@stellar/stellar-sdk";

const server = new Horizon.Server("https://horizon-testnet.stellar.org");

async function watchForPayment(req: OrderRequest, timeoutMs = 300_000): Promise<string> {
  return new Promise((resolve, reject) => {
    const timer = setTimeout(() => {
      close();
      reject(new Error("payment timeout"));
    }, timeoutMs);

    const close = server
      .payments()
      .forAccount(req.destination)
      .cursor("now")
      .stream({
        onmessage(payment: any) {
          if (
            payment.type === "payment" &&
            payment.to === req.destination &&
            payment.amount === req.amount &&
            payment.asset_type === "native"
          ) {
            payment.transaction().then((tx: any) => {
              if (tx.memo === req.memo) {
                clearTimeout(timer);
                close();
                resolve(payment.transaction_hash);
              }
            });
          }
        },
        onerror(err: Error) {
          clearTimeout(timer);
          reject(err);
        },
      });
  });
}
```

## Step 4 — Confirm the Order

Once the payment hash is received:

```ts
app.post("/api/orders/:orderId/pay", async (req, res) => {
  const order = await db.getOrder(req.params.orderId);
  if (!order) return res.status(404).json({ error: "order not found" });
  if (order.status === "PAID") return res.json({ status: "already paid", hash: order.txHash });

  const paymentReq = createPaymentRequest(order.id, order.amount);

  try {
    const txHash = await watchForPayment(paymentReq);
    await db.markOrderPaid(order.id, txHash);
    res.json({ status: "confirmed", hash: txHash });
  } catch (err: any) {
    res.status(408).json({ error: err.message });
  }
});
```

## Edge Cases

| Scenario | Handling |
|----------|---------|
| Buyer sends wrong amount | Amount check fails; order stays unpaid; prompt buyer to correct or issue refund |
| Buyer uses wrong memo | Payment received but cannot be linked to an order; reconcile manually via tx hash |
| Payment arrives after timeout | Query it later with `getTransaction(hash)`; reconcile during a nightly sweep |
| Buyer cancels mid-flow | The SEP-0007 URI simply expires; no on-chain action needed |
| Network congestion | Increase `timeoutMs`; most tx settle within 30 seconds given 5-second ledger close |

## Custom Asset Checkout

For USDC or another anchored asset:

```ts
import { Asset } from "@stellar/stellar-sdk";

const USDC = new Asset(
  "USDC",
  "GA5ZSEJYB37JRC5AVCIA5MOP4RHTM335X2KGX3IHOJAPP5RE34K4KZVN" // Circle testnet issuer
);

// In watchForPayment: check payment.asset_code === "USDC" && payment.asset_issuer === USDC.getIssuer()
```

The buyer's wallet must have a trustline for the asset or the payment will fail with `NO_TRUST`.

## Accuracy Notes

- `cursor("now")` picks up payments after the stream opens; combine with a look-back query (`GET /accounts/{id}/payments?limit=10&order=desc`) to catch payments that arrived before the stream started.
- Memo type must match: `MEMO_TEXT` for short strings, `MEMO_HASH` for 32-byte hashes. Normalize on `MEMO_TEXT` for human-readable order IDs.
- Horizon testnet resets periodically; use mainnet credentials for persistent integration tests.
