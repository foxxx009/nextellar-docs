# Stellar Anchor Integration Basics

An anchor is a service on the Stellar network that issues anchored assets and connects Stellar to real-world payment rails — fiat currencies, other blockchains, or traditional banking systems. This guide covers how to discover an anchor, which SEPs to expect, and a starting checklist for integration.

---

## What Is a Stellar Anchor?

An anchor is a Stellar ecosystem participant that:

- Issues an asset on Stellar (e.g., USDC, EURC, a local stablecoin)
- Accepts deposits of real-world value (fiat or crypto)
- Issues corresponding Stellar tokens to the user's wallet
- Redeems Stellar tokens back to real-world value (withdrawals)
- Publishes metadata and API endpoints for interoperability

Anchors are regulated entities in most jurisdictions. Your dApp doesn't need to become an anchor — it integrates with one.

## Discovering an Anchor: stellar.toml

Every anchor publishes a `stellar.toml` file at its home domain's well-known path:

```
https://<anchor-domain>/.well-known/stellar.toml
```

This file is the anchor's service manifest. It tells your dApp which SEPs the anchor supports and where to find its API endpoints.

### Parsing stellar.toml

```ts
// lib/anchor.ts
import { parse as parseToml } from 'smol-toml';

export async function fetchAnchorToml(anchorDomain: string) {
  const res = await fetch(`https://${anchorDomain}/.well-known/stellar.toml`);
  const text = await res.text();
  return parseToml(text) as Record<string, unknown>;
}
```

### Key Fields to Read

| Field                     | Description                                                |
| ------------------------- | ---------------------------------------------------------- |
| `TRANSFER_SERVER_SEP0024` | URL of the SEP-24 hosted deposit/withdrawal server         |
| `TRANSFER_SERVER_SEP0006` | URL of the SEP-6 synchronous transfer server (legacy)      |
| `WEB_AUTH_ENDPOINT`       | URL of the SEP-10 authentication server                    |
| `KYC_SERVER`              | URL of the SEP-12 KYC endpoint (if not embedded in SEP-24) |
| `NETWORK_PASSPHRASE`      | The Stellar network passphrase the anchor operates on      |
| `ACCOUNTS`                | List of accounts controlled by the anchor                  |
| `VERSION`                 | Version of the stellar.toml spec                           |
| `FRIENDED_PUBLIC_KEYS`    | Keys the anchor trusts for cross-contract calls            |

### Example stellar.toml

```toml
NETWORK_PASSPHRASE="Test SDF Network ; September 2015"
TRANSFER_SERVER_SEP0024="https://testanchor.stellar.org/sep24"
WEB_AUTH_ENDPOINT="https://testanchor.stellar.org/auth"
KYC_SERVER="https://testanchor.stellar.org/kyc"
VERSION="2.0.0"

[[CURRENCIES]]
code="USDC"
issuer="GA5ZSEJYB37JDD5G4FYXWA4D6QECWA7P7FBQMGZI6O7VYBQN7B3B3L3"
display_terminal_decimals=true
is_anchored=true
anchor_asset_type="fiat"
redemption_instructions="Deposit USD via bank transfer."
```

## Common SEPs to Expect

| SEP          | Name                          | Purpose                                        | You Need It If...                                                  |
| ------------ | ----------------------------- | ---------------------------------------------- | ------------------------------------------------------------------ |
| **SEP-0001** | stellar.toml                  | Anchor metadata and service discovery          | Always — this is how you find the anchor                           |
| **SEP-0006** | Deposit and Withdrawal API    | Synchronous REST API for deposits/withdrawals  | The anchor uses the legacy transfer flow (increasingly deprecated) |
| **SEP-0010** | Stellar Web Authentication    | Wallet-signed challenge token for auth         | Always — required for any authenticated anchor interaction         |
| **SEP-0012** | KYC API                       | Collect and upload user identity data          | You handle KYC yourself (not using SEP-24 hosted flow)             |
| **SEP-0024** | Hosted Deposit and Withdrawal | iframe/popup flow for deposits and withdrawals | Most modern anchors — the recommended integration path             |
| **SEP-0038** | Quote API                     | Get a fixed exchange rate before deposit       | You want to show users a price quote before they commit            |

**The standard stack is SEP-0001 + SEP-0010 + SEP-0024.** SEP-0012 is usually handled inside the SEP-24 hosted flow. SEP-0006 is legacy — prefer SEP-0024 for new integrations.

## Integration Flow

```
Your dApp                         Anchor
  |                                 |
  |-- GET /.well-known/stellar.toml ->|
  |<-- TRANSFER_SERVER_SEP0024,     --|
  |    WEB_AUTH_ENDPOINT             |
  |                                 |
  |-- SEP-10 challenge (GET) -----> |
  |<-- unsigned transaction -------- |
  |-- wallet signs XDR ------------>|
  |-- POST signed XDR ------------> |
  |<-- JWT token ------------------- |
  |                                 |
  |-- POST /transactions/deposit/interactive ->|
  |<-- { url, transaction_id } -----|
  |                                 |
  |-- open popup URL -------------- >|
  |-- user completes KYC + deposit   |
  |<-- poll status or webhook -------|
  |                                 |
  |<- anchored asset appears ------- |
```

## Starting Checklist

Use this as a starting point when integrating with an anchor:

- [ ] Fetch and parse the anchor's `stellar.toml` from `/.well-known/stellar.toml`
- [ ] Identify the correct network passphrase (`NETWORK_PASSPHRASE`)
- [ ] Locate the SEP-10 auth server (`WEB_AUTH_ENDPOINT`)
- [ ] Locate the transfer server (`TRANSFER_SERVER_SEP0024` or `TRANSFER_SERVER_SEP0006`)
- [ ] Implement SEP-10 authentication (challenge-response with wallet signing)
- [ ] Store the JWT token for subsequent API calls
- [ ] Implement deposit initiation (SEP-24 interactive or SEP-6 synchronous)
- [ ] Handle the anchor's hosted KYC flow (popup or redirect)
- [ ] Poll for transaction completion or set up webhooks
- [ ] Handle error and rejected states (sanctions, insufficient KYC, jurisdiction restrictions)
- [ ] Test against the SDF reference anchor (`testanchor.stellar.org`) on Testnet

## Testing on Testnet

The SDF provides a reference anchor for testing:

```bash
NEXT_PUBLIC_ANCHOR_DOMAIN=testanchor.stellar.org
NEXT_PUBLIC_STELLAR_NETWORK=testnet
```

The test anchor:

- Accepts any KYC data without verification
- Completes deposits automatically within 30 seconds
- Issues USDC-equivalent tokens on Testnet
- Supports all standard SEP endpoints

This is the fastest way to validate your integration end-to-end without touching real funds.

## Common Pitfalls

| Pitfall                    | Cause                                | Fix                                                       |
| -------------------------- | ------------------------------------ | --------------------------------------------------------- |
| `stellar.toml` fetch fails | CORS, HTTPS mismatch, or wrong path  | Use `https://` and fetch from `/.well-known/stellar.toml` |
| SEP-10 token rejected      | Wrong `home_domain` in challenge     | Pass your app's domain, not the anchor's                  |
| Deposit hangs forever      | Not polling or missing webhook       | Set up polling at 5s intervals or register a webhook      |
| KYC rejected silently      | Anchor returns `needs_more_info`     | Surface the anchor's error message to the user            |
| Wrong network              | Anchor is on mainnet, app on testnet | Match `NETWORK_PASSPHRASE` from `stellar.toml`            |
