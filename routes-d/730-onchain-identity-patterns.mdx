# On-Chain Identity Patterns

Stellar accounts are pseudonymous by design — a public key identifies an account but carries no inherent personal information. This guide surveys common strategies for layering verifiable identity on top of Stellar accounts, their privacy implications, and a small implementation example.

---

## Identity Strategy Comparison

| Strategy | Where identity lives | Trust model | Privacy |
|----------|---------------------|-------------|---------|
| Account data fields | `ManageData` entries on the account | Self-asserted | Public on-chain |
| Attestation by issuer | Custom asset issued to account | Trusted issuer (e.g. KYC provider) | Issuer knows identity |
| Decentralized Identifier (DID) | Off-chain document, anchored by account key | Verifiable credential ecosystem | Selective disclosure |
| Soroban identity contract | Contract storage keyed by account | Contract-enforced rules | Public contract state |

---

## Strategy 1: Account Data Fields

The simplest approach — store a handle or hash directly in the account's data entries.

```ts
import { TransactionBuilder, Operation, Networks, BASE_FEE } from "@stellar/stellar-sdk";
import Horizon from "@stellar/stellar-sdk";

const server = new Horizon.Server("https://horizon-testnet.stellar.org");

async function setIdentityHandle(keypair: Keypair, handle: string) {
  const account = await server.loadAccount(keypair.publicKey());
  const tx = new TransactionBuilder(account, {
    fee: BASE_FEE,
    networkPassphrase: Networks.TESTNET,
  })
    .addOperation(
      Operation.manageData({
        name:  "identity:handle",
        value: Buffer.from(handle, "utf8"), // max 64 bytes
      })
    )
    .setTimeout(30)
    .build();

  tx.sign(keypair);
  return server.submitTransaction(tx);
}

// Read it back
async function getHandle(publicKey: string): Promise<string | null> {
  const account = await server.loadAccount(publicKey);
  const entry   = account.data_attr["identity:handle"];
  return entry ? Buffer.from(entry, "base64").toString("utf8") : null;
}
```

**Trade-off**: Entirely self-asserted. Anyone can write anything. Useful for display names, not for KYC-grade identity.

## Strategy 2: Attestation via Asset Issuance

An authorized issuer sends a non-transferable asset to accounts that have passed verification.

```ts
import { Asset, Operation } from "@stellar/stellar-sdk";

const KYC_ASSET = new Asset("VERIFIED", "GISSUER_PUBLIC_KEY_HERE");

// Issuer sends 0.0000001 of VERIFIED to the verified account
async function issueAttestation(issuerKeypair: Keypair, recipientPublicKey: string) {
  const account = await server.loadAccount(issuerKeypair.publicKey());
  const tx = new TransactionBuilder(account, {
    fee: BASE_FEE,
    networkPassphrase: Networks.TESTNET,
  })
    .addOperation(
      Operation.payment({
        destination: recipientPublicKey,
        asset:       KYC_ASSET,
        amount:      "0.0000001",
      })
    )
    .setTimeout(30)
    .build();

  tx.sign(issuerKeypair);
  return server.submitTransaction(tx);
}

// Anyone can verify by checking account balances
async function isVerified(publicKey: string): Promise<boolean> {
  const account  = await server.loadAccount(publicKey);
  return account.balances.some(
    (b: any) => b.asset_code === "VERIFIED" && b.asset_issuer === KYC_ASSET.getIssuer()
  );
}
```

Make the asset non-transferable by setting `AUTH_REVOCABLE` and `AUTH_REQUIRED` flags on the issuer account.

## Strategy 3: Soroban Identity Contract

A contract stores a mapping from account address to a verified identity hash, controlled by an admin.

```rust
#![no_std]
use soroban_sdk::{contract, contractimpl, contracttype, Address, BytesN, Env, Symbol};

#[contracttype]
pub enum DataKey {
    Admin,
    Identity(Address), // address → sha256 hash of identity document
}

#[contract]
pub struct IdentityRegistry;

#[contractimpl]
impl IdentityRegistry {
    pub fn initialize(env: Env, admin: Address) {
        assert!(!env.storage().instance().has(&DataKey::Admin), "already initialized");
        env.storage().instance().set(&DataKey::Admin, &admin);
    }

    pub fn attest(env: Env, caller: Address, subject: Address, id_hash: BytesN<32>) {
        caller.require_auth();
        let admin: Address = env.storage().instance().get(&DataKey::Admin).unwrap();
        assert!(caller == admin, "unauthorized");
        env.storage().instance().set(&DataKey::Identity(subject.clone()), &id_hash);
        env.events().publish((Symbol::new(&env, "attest"), subject), id_hash);
    }

    pub fn revoke(env: Env, caller: Address, subject: Address) {
        caller.require_auth();
        let admin: Address = env.storage().instance().get(&DataKey::Admin).unwrap();
        assert!(caller == admin, "unauthorized");
        env.storage().instance().remove(&DataKey::Identity(subject));
    }

    pub fn get_identity(env: Env, subject: Address) -> Option<BytesN<32>> {
        env.storage().instance().get(&DataKey::Identity(subject))
    }
}
```

## Privacy Considerations

| Concern | Impact | Mitigation |
|---------|--------|-----------|
| Account data is public | Anyone can read `ManageData` entries | Store only hashes, not raw PII |
| Asset balances are public | KYC attestation asset is visible to all | Use a zero-amount locked asset; amount reveals nothing |
| Contract state is public | Identity hashes on-chain are permanent | Hash with a salt; off-chain document stays private |
| Linking accounts | Multiple accounts can be linked by common signers or data | Use separate accounts per identity context |

---

## Choosing a Strategy

- **Hobby project / display name**: Account data fields — simple, no dependencies.
- **Regulated product needing KYC**: Attestation asset from a licensed issuer — auditable, revocable.
- **Interoperable identity across dApps**: DID anchored by the account key with selective disclosure — most privacy-preserving.
- **On-chain access control in a Soroban contract**: Identity registry contract — query identity in contract logic without off-chain round trips.

---

## Accuracy Notes

- `ManageData` values are capped at 64 bytes; store a URL or hash if you need more.
- `AUTH_REVOCABLE` on the issuing account allows the issuer to clawback an attestation asset; without it, issuance is permanent.
- DIDs on Stellar use the `did:stellar` method; refer to the Stellar DID specification for document format and resolution.
